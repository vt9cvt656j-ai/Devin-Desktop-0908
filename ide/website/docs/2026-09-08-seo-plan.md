## 0. 结论（先看这个）

官网是 Vite + React 的客户端 SPA。nginx 对未知路径 `try_files $uri $uri/ /index.html`，所以 `/changelog`、`/docs`、`/rankings` 的 HTTP 状态永远是 200，HTML 壳永远是同一份 `index.html`。

Google 能跑 JS（[JavaScript SEO 基础知识](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)，文档最后更新 2026-03-05），但社交抓取器、百度、部分预览机器人**不跑 JS**。当前线上：

| 缺口 | 现状 | 证据（2026-09-08 实抓） |
|---|---|---|
| robots.txt | Cloudflare 托管前缀 + 源站 SPA HTML 拼在一起，不是一份干净的 txt | `GET https://mrday.one/robots.txt` 3418 bytes：先是 `Content-Signal` / `GPTBot Disallow`，后接 `<!doctype html>` |
| sitemap.xml | 不存在，回落到首页 HTML | `GET https://mrday.one/sitemap.xml` 1582 bytes，与首页壳相同 |
| Open Graph / Twitter Card | `index.html` 没有 | `ide/website/index.html` 只有 title + description |
| canonical | 没有 | 同上 |
| 每页独立 description | 只有首页静态一条 | `App.tsx` 只改 `document.title` |
| 未知路径 404 | 全部 200 | `mrday-site.conf` `try_files ... /index.html` |
| `/app/` 内嵌 IDE | 可被当独立页索引 | `public/app/index.html` 只有 `<title>Mr. Day One</title>` |

本轮**不引入 SSR / Next.js**。栈是 Vite SPA，部署脚本按静态 `dist/` 上传。SEO 用「静态 HTML 壳 + 客户端补全 + 静态 robots/sitemap」就能把可验收项做完。预渲染是可选的 P2，不是前提。

## 1. 架构与边界（改之前必须守住）

```
浏览器 / 爬虫
    │
    ▼
nginx mrday.one
    location /assets/  →  hashed 静态，immutable
    location /         →  try_files $uri $uri/ /index.html
    │
    ▼
ide/website/dist/                    ← npm run build 产出
    index.html                       ← 营销站壳（本计划主战场）
    robots.txt / sitemap.xml         ← 新增，必须是真实文件，不能走 SPA 回退
    og-image.png                     ← 新增
    app/                             ← 内嵌 IDE 构建产物（--base=/app/）
        index.html                   ← 只加 noindex，不改 IDE 逻辑
```

**不要动：**

- `ide/` 主工程、`public/app/` 的 JS/CSS bundle、`--base=/app/` 构建流程。
- `server/src/`、账号控制台 `code.mrday.one`。
- 首页区块的视觉构图、GSAP/动效、文案大改（文案只在 title/description 层对齐，不重写产品叙事）。
- 把 SPA 改成 Next.js / 加 react-router。现有 `PAGES` 表已经够用。

**域名约定（已有）：**

- 规范域：`https://mrday.one`（apex）。
- `www.mrday.one`：HTTP 301 到 apex；当前无 DNS 记录，不要把它写进 sitemap。
- `www.michaelide.xyz`：已 301 到 `https://mrday.one$request_uri`（`mrday-site.conf` 末块）。
- `code.mrday.one`：控制台，不是营销站，sitemap 不收录。

## 3. 实施阶段

### P0 — 索引入口与分享（不做这些，后面全白做）

**目标：** 爬虫能发现站点地图；微信/X/iMessage 分享出卡片；`/app/` 不进索引。

#### P0.1 `public/robots.txt`

```
User-agent: *
Allow: /

Disallow: /app/
Disallow: /app/*

Sitemap: https://mrday.one/sitemap.xml
```

验收：`curl -sI https://mrday.one/robots.txt` → `200`，`Content-Type: text/plain`。body **不能**含 `<!doctype` / `<html`。

注意：nginx `location ~ /\.(?!well-known)` 只挡点文件，`robots.txt` 不受影响。`try_files $uri $uri/ /index.html` 会先命中真实文件，所以必须是磁盘上的真文件，不能靠 SPA 路由。

线上比「文件不存在」更糟：Cloudflare AI Crawl Control 在边缘注入了一段合法规则（`search=yes,ai-train=no`，并 Disallow `GPTBot` / `ClaudeBot` / `Google-Extended` / `Bytespider` 等），源站又把 `index.html` 拼在后面。Google 解析 robots.txt 遇到 HTML 可能提前停，规则是否完整生效不确定。落地真实文件后再 curl 一次。若 Cloudflare 仍 prepend Managed content，可以保留那段（`search=yes` 对 Googlebot 友好），但后面绝不能再跟 HTML。

`GPTBot` / `ClaudeBot` / `Google-Extended` 的 Disallow **不影响 Googlebot 收录**，但会挡住 ChatGPT / Claude / Gemini 训练侧抓取。若以后要做 AI 引用可见性，去 Cloudflare 控制台放开，不要在本站 robots 里再写一份冲突规则。GitHub 对 Bing 单独 `Disallow: /copilot/`，和我们把 `/app/` 踢出索引是同一类决策：产品 UI 不当独立结果。

#### P0.2 `public/sitemap.xml`

静态即可，路由就这几条，不需要构建时生成：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://mrday.one/</loc><changefreq>weekly</changefreq><priority>1.0</priority></url>
  <url><loc>https://mrday.one/docs</loc><changefreq>weekly</changefreq><priority>0.8</priority></url>
  <url><loc>https://mrday.one/changelog</loc><changefreq>weekly</changefreq><priority>0.7</priority></url>
  <url><loc>https://mrday.one/rankings</loc><changefreq>daily</changefreq><priority>0.5</priority></url>
</urlset>
```

`/docs/<slug>` 等文档目录稳定后再追加。不要收录 `/app/`、hash 锚点、`code.mrday.one`。  
Google 官方建议：sitemap 用 Search Console 提交；放进 robots.txt 的 Sitemap 行是发现通道（[构建站点地图](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)）。

验收：`curl -sI https://mrday.one/sitemap.xml` → `200`，`application/xml`；四个 `<loc>` 都能 200。

改 `ide/website/index.html` `<head>`，在现有 title/description 后追加。这些必须写在**原始 HTML**里：社交抓取器不跑 JS（[ogp.me](https://ogp.me/) 要求 `og:title` / `og:type` / `og:image` / `og:url` 四件套）。

<meta property="og:description" content="（与现有 meta description 同一句）" />

<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />

`og-image.png`：新建 `public/og-image.png`，1200×630。**不要**直接用 512×512 的 `logo.png` 当 og:image（会被裁成小图标）。图可以是现有 IDE 截图（`ide-window` 用的那张）加品牌条，不新写视觉系统。

### P1 — 每页独立元数据（SPA 内部）

**目标：** 渲染后的 DOM 里，每个可分享 URL 都有自己的 title / description / canonical。Google 渲染后会用这些（官方明确可以用 JS 改 title 和 description）。canonical **不要**在 JS 里改成跟原始 HTML 不同的值——官方不建议。做法：原始 HTML 放首页 canonical；子页用 JS **替换为与当前 URL 一致的值**（原始 HTML 里那条会被覆盖成同一文档的规范地址，而不是「改成另一个页面」）。更稳的等价：子页 JS 先移除壳上的首页 canonical，再写入当前 URL。两条都符合「不要把 canonical 改成另一个页面还留着旧值」。

#### P1.1 在 `App.tsx` 的 `PAGES` 表加 `description`

不要引入 react-helmet。这个站没有路由库，一个 `applyPageMeta(page)` 函数就够：

```
function applyPageMeta(opts: {
  title: string;
  description: string;
  canonical: string;      // 绝对 URL
  robots?: string;        // 默认 index,follow
})
```

写入：`document.title`、`meta[name=description]`、`link[rel=canonical]`、`meta[property=og:title|og:description|og:url]`、`meta[name=twitter:title|twitter:description]`。没有节点就 `createElement`。

建议文案（可微调，长度 description ≤ 155 字）：

| 路径 | title | description |
|---|---|---|
| `/` | 保持 `index.html` 现有 title | 保持现有 description |
| `/changelog` | Update log — Mr. Day One | Notable changes across the editor, the gateway, the account console, and this site. |
| `/rankings` | Rankings — Mr. Day One | Accounts ranked by real usage through the gateway. |
| `/docs` | Docs — Mr. Day One | Guides for installing and using Mr. Day One. |
| `/docs/<slug>` | `{articleTitle} — Docs — Mr. Day One` | 文章第一段或 landing 的固定句；由 DocsPage 在加载成功后调用 `applyPageMeta` |
| 未知路径 | Page not found — Mr. Day One | robots=`noindex` |

`/docs/<slug>` 现在 `PAGES.title` 写死「文档」。要在 `DocsPage` 拿到 `doc.title` 之后覆盖，不要停在「文档 — Mr. Day One」。缺失文档（已有 `title="这一页不存在"` UI）必须 `noindex`，并按 Google 的 SPA soft-404 建议：加 `<meta name="robots" content="noindex">`（[JS SEO 基础知识 · 避免 soft 404](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)）。

#### P1.2 真 404

`PAGES` 匹配失败且 pathname 不是 `/` 时，不要再渲染整页首页。新增一个很薄的 `NotFoundPage`（沿用现有 Navbar/Footer），HTTP 仍然是 200（SPA 改不了状态码）。用 `noindex` 避免 soft-404 进索引。

可选增强（P2）：nginx `location = /not-found { return 404; … }` + JS `window.location = '/not-found'`。P1 用 noindex 就够。

验收：打开 `/this-is-not-a-page`，标题不是产品 slogan，head 里有 `noindex`；首页 `/` 行为不变。

#### P1.3 页脚补可抓取链接

`footer.tsx` 现在只有 `#features` 等锚点。爬虫要靠 `<a href>` 发现 URL（Google 原文：只有带 href 的 `<a>` 才算链接）。在 Product 或另开一列加：

- Docs → `/docs`
- Changelog → `/changelog`
- Rankings → `/rankings`

锚点列保留。不要链到 `/app/`。

验收：`footer.tsx` 源码里能看到这三个绝对路径；线上查看网页源代码（渲染后）也能看到。

### P2 — 结构化数据、文档索引、性能（有余力再做）

#### P2.1 JSON-LD

对标 Cursor 首页（2026-09-08 原始 HTML，两条 JSON-LD，用 `@id` 互指）：

- `Organization`：`name` / `url` / `logo` / `sameAs`（X、GitHub 等真实账号）/ `foundingDate`（有再写）
- `WebSite`：`url` + `publisher` 指回 Organization 的 `@id`

不要编 `aggregateRating`、不要编安装量。`SoftwareApplication` 是 Google 仍支持的类型（claude-seo `seo-schema`，2026-06 状态表），有稳定下载入口后再加，字段只用真实的 `name` / `applicationCategory` / `operatingSystem` / `url`。

JSON-LD **写进 `index.html` 原始 HTML**，不要只靠 JS 注入。`seo-schema` 引用 Google 2025-12 JS SEO 说明：JS 注入的 structured data 可能延迟处理。社交抓取器同样不跑 JS。Changelog / 文档页可用 JS 补 `TechArticle`，官方允许，但首页这两条必须在壳里。

Cline 首页把 OG 图放同源 `https://cline.bot/cline_og_img.png`，Cognition 用 1200×630 jpeg。我们按 P0.3 走同源 `https://mrday.one/og-image.png`，不要用 512 的 logo。

**不要**给 Rankings 写 `ItemList` 除非确认公开数据稳定且愿意被缓存。

#### P2.2 文档 slug 进 sitemap

`DocsPage` 已有 `/docs/<slug>` 的 `pushState` 和真实 `<a href="/docs/${p.slug}">`。等文档目录不再「正在写」，用构建脚本把 slug 列表写进 `sitemap.xml`。现在落地页还可能是空状态，先不要把不存在的 slug 写进去。

#### P2.3 预渲染（可选，非必须）

Vite SPA 继续。若发现百度 / 社交仍抓不到子页正文，再加 `vite-plugin-prerender` 或构建时对 `/` `/docs` `/changelog` `/rankings` 吐静态 HTML。这会动构建，单独开任务，不要和 P0/P1 绑在一起。

Google 自己说「依然建议 SSR 或预渲染」，但同时也完整支持渲染 JS。本站优先把静态壳和 sitemap 做对。

#### P2.4 字体与 LCP

`index.html` 现拉 Google Fonts 三条家族。P2 再考虑 `font-display: swap` 已有、或自托管 woff2。不作为本轮 SEO 阻塞项。Core Web Vitals 另开任务，不塞进这次。

#### P2.5 hreflang / 中文站

站点 `lang="en"`，文档页中文、changelog 英文、docs title「文档」混用。本轮**不做** i18n 分站。P2 若要做：子目录 `/zh/`，每页 hreflang + x-default，而不是靠 JS 切换同一 URL 的语言（同一 URL 两种语言会把信号打乱）。

### 7.1 从竞品抽出、能直接落到本站的 8 条

1. **原始 HTML 里就要有 title + description + canonical + og 四件套 + twitter:card。** Cursor / Cline / Cognition 全是 SSR 所以壳里就有正文；我们是 SPA，至少壳里要有首页这套（P0.3），子页靠 JS 覆盖（P1.1）。社交抓取器不跑 JS。
2. **`og:image` 必须是绝对 URL、约 1200×630、同源静态文件。** Cline：`https://cline.bot/cline_og_img.png`。Cognition：jpeg 带 width/height/alt。不要用 512 的 `logo.png`。
3. **JSON-LD 用 `Organization` + `WebSite` 互指 `@id`，不要编评分。** Cursor 首页就是这个最小集。`SoftwareApplication` 等有稳定下载页再加。
4. **`robots.txt` 必须是纯文本。** Anthropic 三行就够。Cursor 额外 Disallow 失败页。GitHub 把产品 UI 踢出部分引擎。我们 Disallow `/app/`。
5. **sitemap 是真 XML，且写进 robots 的 `Sitemap:` 行。** Cursor 论坛单独一张图；营销页另有 `sitemap.xml`。我们四条公开路由就够。
6. **真 `<a href>` 发现文档/changelog。** 竞品文档都在独立子域或路径，footer/nav 有抓得到的链接。我们 navbar 已有，footer 还缺（P1.3）。
7. **hreflang 只在真有分语言 URL 时做。** Cursor 是 `/cn/` `/ja/` 子目录，不是同一 URL 切文案。本站 `lang="en"`、文档中英混排——P2 之前不做（原 2.5 / P2.5 仍成立）。
8. **`llms.txt` 对 Google 搜索无效。** Cognition / Cursor 有文件；[Google AI 优化指南](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)（文档更新 2026-07-15）明确：不必为 Google（含 AI 概览 / AI 模式）建 `llms.txt` 或其它 AI 专用标记，不帮也不伤排名。可选 P2：给人/ChatGPT 当站点说明书，**不作为 Google SEO 项**。

### 7.2 明确不抄的

| 竞品做法 | 为什么不抄 |
|---|---|
| Next.js / SSR 把整页正文打进首包（Cursor 645 KB HTML） | 本计划边界：Vite SPA + 静态壳。Google 能渲染 JS（文档 2026-03-05），优先把壳和 sitemap 做对 |
| description 写「8M+ developers」 | 没有可核验数字就写，等于给 Google 虚假声明 |

| 十语言 hreflang | 没有 `/zh/` 实体页 |
| 把 `llms.txt` 当排名杠杆 | Google 官方否定 |
| 为每个长尾再造一页 | 违反规模化内容滥用政策；指南原文：不要为扇出查询堆页面 |

## 9.1 Google Search Console 接入（2026-09-08）

原 P3 写成「有账号再做」，仓库里因此零 Google 产品配置。分层错了：网页能被读到（P0/P1）和站长能监控抓取（GSC）是两件事，后者缺验证凭据，但不能把验证槽、robots 分组和提交步骤也一起省略。
