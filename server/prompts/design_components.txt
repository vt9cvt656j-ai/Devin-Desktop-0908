# michael-design component layer: one control, done properly

Retrieve first: `knowledge_search(domain="michael-design")` carries per-control blueprints under `[components/…]` with sizing scale, variant API, state matrix, keyboard/ARIA contract and motion numbers. Search the control by name — Chinese names hit directly. A component request is one control, not a page section: no project scaffold, no direction picker, no restyling what you were not asked about.

## The contract every control owes

- **State matrix, every variant, no exceptions**: rest, hover, active/pressed, focus-visible, disabled, and — where it can wait on something — loading. A variant that only has a rest style is unfinished. Focus-visible is never removed and never merged into hover; keyboard users cannot see hover.
- **Sizing scale before variants**: heights from one scale (commonly 32/36/40px); controls that share a row share the scale. Touch targets reach 44px through padding or a pseudo-element, not by growing the visual box.
- **Consume the project's token carrier**: business components use the semantic classes it exposes (background/foreground/card/primary/muted/border/ring/radius…), never raw hex or one-off values. Establish those roles yourself only when the project has none.
- **Variant API, not one-off classes**: express variants and sizes through `cva` with `defaultVariants`, merging incoming `className` through `twMerge(clsx(...))` so callers can override. Callers pass `variant="secondary" size="sm"`, not class strings. Support `asChild` where the control may become a link.
- **Install the primitive, never hand-write a shadcn-style copy**: `npx shadcn@latest init`, then `npx shadcn@latest add button dialog select`. A lookalike inherits none of the keyboard, focus or portal behaviour.
- **Keyboard and ARIA are part of the component**, not a later pass: roles, arrow/Home/End behaviour, `aria-expanded`/`aria-selected`/`aria-invalid`, the accessible name on icon-only controls, and where focus goes on open and close. Build on a headless primitive — the project's existing one, or Radix/Base UI on the default branch, installed rather than imitated.
- **Motion numbers, not vibes**: 120–160ms hover, 80–100ms press, 150–250ms open/close, one easing page-wide. Never scale a rectangular control containing text. Hold the width when a label swaps for a spinner, or the row jumps under the pointer mid-click.
- **The unhappy paths ship with it**: empty, loading skeleton matching the real layout, error with retry, read-only where it differs from disabled.

## Icons and labels

Map "business concept → object/action/state → icon name" first, then take the icon from the project's set (or `iconify_search`) at one consistent style and weight; the default branch may use Lucide. Semantics must match (AI = Bot/Cpu, security = ShieldCheck, analytics = Chart); Sparkles/Wand mean actual sparkle or magic only. No bitmaps, emoji or ad-hoc hand-written SVG in buttons and toolbars. An icon-only control needs an `aria-label` naming the action and its object; never encode meaning in colour alone.
